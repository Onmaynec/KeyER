# KeyER v0.7.0 — Studio UX Overhaul

## Цель релиза

v0.7.0 улучшает **первый запуск, редактирование исходного материала, навигацию и настройку интерфейса**. Движки Text, Code, Human Behavior и локальные интеграции IDE продолжают использовать прежнюю архитектуру. В этой версии не добавляются очереди или история сессий: акцент сознательно перенесён на удобство существующей программы.

## Новое главное окно

### Понятное начало работы

Пустой редактор теперь показывает отдельный интерактивный слой с кнопками «Вставить текст» и «Открыть файл», а не только пустое поле. После появления первого символа слой автоматически скрывается. Клик в пустую область возвращает клавиатурный фокус редактору.

Слева есть пошаговая памятка: добавить исходник, выбрать целевое окно и запустить набор горячей клавишей. По мере появления исходника первый шаг получает подтверждение. При малой высоте окна памятка скрывается, чтобы не перекрывать важные элементы управления.

Под профилем видны его скорость и вероятность опечаток. Справа от сочетаний запуска показывается **приблизительная** длительность по базовому CPM без учёта случайных пауз, ошибок и исправлений. Важно: это не обещание реального времени завершения.

### Работа с файлами

- **Сохранить** и **Ctrl+Shift+S** открывают стандартный Windows Save As. KeyER сам не записывает введённый текст на диск и не загружает его в облако.
- При перетаскивании ровно одного обычного файла в редактор он открывается как текст. Для размеров более 2 МБ запрашивается подтверждение; файлы более 10 МБ не загружаются.
- При открытии другого файла поверх изменённого исходника KeyER запрашивает подтверждение, не удаляя старый текст при отказе или ошибке чтения.
- **Очистить** также требует подтверждения, если редактор непустой.
- Пока идёт набор, импорт, очистка, изменение режима и сохранение исходника заблокированы.
- После открытия файла имя сохраняется для выбора языка Code даже после локальных правок, а значок у имени показывает несохранённые изменения. Полный путь файла в интерфейсе не раскрывается.

### Поиск в исходнике

Поиск теперь показывает количество и порядковый номер совпадений, поддерживает циклическое перемещение вперёд/назад и переключатель регистра. Можно открыть поиск из выделенного фрагмента текста.

| Действие | Управление |
| --- | --- |
| Открыть поиск | Ctrl+F |
| Следующий результат | Enter или кнопка ↓ |
| Предыдущий результат | Shift+Enter или кнопка ↑ |
| Учитывать регистр | Aa |
| Закрыть поиск | Esc |
| Сохранить копию исходника | Ctrl+Shift+S |

Используется чистый алгоритм SnippetSearch; он не изменяет текст редактора. Для защиты от долгих задержек на огромных текстах отображение ограничено максимум 10 тысячами найденных совпадений.

### Новые состояния и доступность

- Основной Start отключён для пустого документа и во время выполнения, а Pause/Stop отражают состояние движка.
- Сообщения об ошибках и предупреждениях различаются по цвету; полное содержимое длинного сообщения доступно в tooltip.
- StudioButton теперь может отображать выровненный влево текст и индикатор активного раздела, оставаясь обычной доступной WinForms-кнопкой.
- Добавлены оформления для собственного окна краткого руководства и подтверждений, чтобы системные модальные сообщения не нарушали общий визуальный стиль.
- На небольших экранах скрываются только дополнительные элементы, тогда как Start, Pause, Stop и профиль остаются доступными.

## Настройки Studio

Пять категорий: «Поведение», «Текст», «Код», «Клавиши», «Оформление». Названия в меню сокращены, чтобы не обрезаться при обычной ширине боковой панели.

В верхней части параметров профиля появился поиск по подписи поля. Поиск работает **внутри выбранного раздела** и сообщает число найденных настроек; Esc очищает запрос. Результат не приводит к изменению значений.

Оформление теперь имеет две колонки: параметры слева и **живой предпросмотр интерфейса справа**. Тема Dark / Light / System и акцент Iris / Ocean / Mint / Amber видны на миниатюрном макете без изменения основного окна и до сохранения настроек. Нажатие «Отмена» не применяет экспериментируемые значения.

## Технические детали и приватность

- Все изменения локальные: C# / .NET 8 / WinForms / GDI+. Веб-платформа, API, внешняя аналитика и сетевые ресурсы не нужны.
- SettingsStore продолжает хранить только настройки и профили. Исходный текст не сохраняется в AppSettings автоматически.
- Сохраняются существующие команды набора, контроль целевого окна, пауза/стоп и опциональная IDE-интеграция.
- Сценарии массового поиска используют ограничения, а UI получает реальные Windows STA regression tests.
- CI дополнительно создаёт снимки настоящих WinForms-окон: главный редактор, экран пустого документа, поиск, настройки и оформление.

## Проверки совместимости

**CI:** запуск тестов движков, проверка SnippetSearch (обе ориентации, кириллица, emoji, регистр, ограничение на 10 000 совпадений), конструирование WinForms UI, работоспособность предпросмотра темы, наличие действий пустого экрана.

**Ручная проверка:** на Windows 10/11 повторить смену темы, resize при 100/125/150% DPI, работу Drag & Drop, Save As, подтверждений очистки, поиск клавиатурой, запуск с горячей клавиши и переориентацию фокуса между окном KeyER и целевым приложением.

### Границы заявлений

CI не может подтвердить работу кликов на пользовательском мониторе с любым DPI или текстовым полем. Снимки получены из реальных Windows Forms на GitHub Actions; они не являются фейковыми изображениями интерфейса. При необходимости корректности вывода в VS Code нужно включать отдельный режим сверки IDE и проверять результат на реальном ПК.
