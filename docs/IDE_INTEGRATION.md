# KeyER v0.4.0 — IDE Integration

## Как работает

KeyER по-прежнему передаёт символы через Windows SendInput. IDE-интеграция проверяет состояние целевого редактора перед набором и сравнивает результат после.

Параметр **IDE: проверка итогового кода** (в настройках Code-профиля) имеет три состояния:

| Режим | Поведение |
| --- | --- |
| Отключено | Обычный набор через клавиатуру, без связи с IDE |
| Проверить без исправления | Проверка пустого документа перед набором и сравнение после него |
| Проверить и исправить | Если есть расхождение, с явного разрешения пользователя содержимое исходно пустого документа исправляется через API IDE, затем проверяется повторно |

Для проверяемого набора нужны: **пустой текстовый документ**, один курсор в начале, тот же активный редактор на протяжении ввода и не более 250 000 символов кода.

Если интеграция включена, а связь с IDE не установлена, KeyER **не начинает** набор. Это защищает от ложных сообщений о точности.

## VS Code на Windows

1. Установите VSIX из артефакта сборки (Extensions → меню «...» → Install from VSIX).
2. Перезапустите VS Code, запустите KeyER. В статусной строке расширения отображается подключение.
3. Создайте пустой файл, поставьте курсор в начало. В KeyER выберите Code и режим «Проверить и исправить».
4. Вернитесь в VS Code, запустите набор через Ctrl+Alt+F5. В конце программа сообщит о совпадении или исправлении.

Расширение подключается локально через Windows Named Pipe с именем **KeyER.IdeBridge.v1** и ограничением **CurrentUserOnly** (тот же пользователь и уровень привилегий). Нет TCP-порта, облачной передачи кода или стороннего API.

### Протокол

- **prepare:** проверка фокуса, пустоты документа, одного курсора без выделения. В ответ возвращаются одноразовый идентификатор сессии и настройки языка, автоотступов, автоскобок, автокавычек, форматирования и табуляции.
- **invalidated:** при смене вкладки, фокуса окна или закрытии документа KeyER останавливает набор.
- **complete:** исходный текст уже введённого кода передаётся расширению только локально для сравнения с активным документом. Если разрешён Repair, используется VS Code TextEditor.edit; документ **не сохраняется на диск**.
- **cancel:** после остановки отменяется сессия проверки.

Расширение не передаёт в KeyER содержимое чужих документов. Обратный ответ содержит только статус совпадения или исправления. Содержимое исходного кода не записывается в диагностический журнал.

### Автоотступы, автозакрытие и IntelliSense

KeyER читает настройки IDE, **но не изменяет глобальную конфигурацию VS Code**. При включённом IntelliSense и автоскобках промежуточный текст может отличаться от исходника. В конце разрешённая коррекция может привести исходно пустой документ к точному тексту. Форматирование по команде Save после проверки может снова изменить содержимое.

Эта версия не управляет подсказками IntelliSense по смыслу и не гарантирует, что каждое промежуточное действие повторяет работу программиста.

## Visual Studio 2022 (экспериментально)

KeyER ищет COM DTE-объект по PID активного процесса devenv.exe через Running Object Table. В проверяемом режиме запрашивается пустой TextDocument. Во время набора приложение периодически проверяет активность того же документа, затем сравнивает содержимое через DTE и, при разрешении, использует EditPoint.ReplaceText для исправления.

Visual Studio может блокировать COM-автоматизацию во время выполнения операций либо использовать нестандартные документы. Успешность этого механизма зависит от версии и настроек Visual Studio и нуждается в испытании на реальной Windows-машине. Если проверяемый режим недоступен, его можно отключить и использовать прежний обычный набор клавиатурой.

## Тесты и ограничения

В CI запускаются регрессионные проверки точности Text/Code, тест соединения Windows Named Pipe и симулированные Node-тесты VS Code для пустого редактора, запрета непустого, проверки, исправления и потери фокуса.

**CI не запускает настоящий Visual Studio или VS Code.** Подтверждение точности в реальных IDE требуется отдельно (см. TESTING.md). Исправление целого буфера создаёт операцию Undo; проверьте код перед сохранением. Не используйте режим для документов с несохранённой чужой работой.
