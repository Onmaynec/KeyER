# KeyER — устройство приложения

## Технологии

- Windows 10/11, WinForms, C# и .NET 8
- Win32 RegisterHotKey для глобальных сочетаний с MOD_NOREPEAT
- Win32 SendInput для Unicode-символов и управляющих клавиш
- JSON в %LOCALAPPDATA%\KeyER\settings.json для профилей и клавиш
- Разделение GUI (MainForm, SettingsForm), модели (Model), Win32-интеграции (Native) и движка (TypingEngine)

## Последовательность

1. Пользователь выбирает Text или Code, вставляет текст или импортирует файл.
2. Горячая клавиша старта запоминает foreground HWND. При запуске кнопкой предусмотрен отсчёт.
3. Движок делает снимок текста и профиля, чтобы изменения настроек не нарушили текущий запуск.
4. На рабочем потоке движок отправляет символы в активное окно с индивидуальной задержкой.
5. Перед стартом ожидается отпускание Ctrl/Alt/Shift/Win после нажатия глобального сочетания.
6. Каждый Unicode-символ и управляющая клавиша проходят проверку целевого активного окна.
7. Часть букв намеренно заменяется, пропускается, повторяется или меняется местами, затем исправляется через курсор и Backspace. Отложенные ошибки не пересекают границы слов.
8. Перед каждым вводимым действием движок проверяет отмену, паузу и совпадение foreground HWND.
9. По завершении GUI получает статус и прогресс. При смене окна набор прекращается.

## Code: ограничения

Определение языка осуществляется по расширению импортированного файла и эвристикам исходного текста. На этом этапе программа **не подключается к API VS/VS Code**, не управляет подсказками IntelliSense и не измеряет документ после набора. Исправления, взаимодействие с автоотступом и горячие клавиши могут отличаться в зависимости от IDE и её настроек.

Опциональное ClearAutoIndent: после Enter в режиме Code программа нажимает Home дважды, затем Shift+End, выделяя автоматически вставленный редактором текст в текущей строке; следующий исходный символ заменяет выделение. Подходит не для всех сред. По умолчанию отключено.

Разные профили редакторов пока используются как метаданные для будущих интеграций, а не как гарантия IDE-специфичного поведения.

## Надёжность v0.1.1

- Движок использует интерфейс ITypingDevice: Windows-реализация вызывает Win32, тестовая имитирует ввод в памяти.
- Исправлены расчёт отложенных символов при перестановке букв и проверка фокуса во время коррекции.
- Убраны несимметричные Home/End при проверке строки в режиме Text.
- Win32-отправка пытается отпустить клавиши при частичной доставке SendInput.
- RegisterHotKey не прибавляет MOD_WIN к случайным клавишам. Windows-модификатор в настраиваемых сочетаниях пока не поддерживается.
- SettingsStore атомарно сохраняет JSON и резервную копию; при повреждении основной версии пытается загрузить резервную.
- В diagnostics.log журналируются только время, компонент, тип исключения и HRESULT. Текст пользователя, заголовки окон и имена файлов намеренно не записываются.
- Тесты проверяют итоговую строку при множестве случайных сценариев без реальных SendInput.

## Безопасность и управление

- KeyER не выводит текст в собственное окно и отменяет текущий ввод при переключении на другое активное окно.
- Быстрый стоп через глобальную клавишу, по умолчанию Ctrl+Alt+F7.
- При остановке уже отправленные символы не откатываются.
- Приложения с повышенными правами, защищённые поля и некоторые терминалы могут игнорировать инъекцию.
- Во время использования не нажимайте клавиши вручную в целевом поле: это повлияет на положение курсора и результат.

## Дальнейшая разработка

Для более точного режима Code потребуется отдельная интеграция с конкретными редакторами, определение их настроек автозакрытия и табуляции, а также механизм подтверждения результата. Эти функции не следует обозначать как готовые в v0.1.0.
