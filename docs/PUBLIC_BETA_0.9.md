# KeyER v0.9.0 — Public Beta

## Статус

Public Beta — функционально собранная ветка, но **не обещание стабильности 1.0.0**. Цель версии — выявить реальные проблемы запуска, настроек, файлов и совместимости. Отдельные пользовательские проверки с разным DPI, Visual Studio, VS Code, Блокнотом, браузерами, UAC и защитным ПО остаются обязательными.

## Изменения

### 1. Один экземпляр приложения

При стандартном запуске KeyER создаёт именованный локальный Windows mutex. Новый экземпляр с тем же именем не открывает второе окно и не конкурирует за глобальные горячие клавиши или файл настроек. Вместо этого он показывает инструкцию вернуться к существующему окну. Механизм работает на уровне пользовательского сеанса Windows, а не на других устройствах.

При нормальном завершении mutex освобождается. Это не удаляет настройки и не меняет содержимое открытого редактора. Отдельные процессы тестов интерфейса не блокируются запуском реального приложения.

### 2. Более безопасное сохранение исходника

Ручные действия «Сохранить» и Ctrl+S/Ctrl+Shift+S используют атомарную запись:

1. создаётся уникальный временный файл в папке назначения;
2. исходник полностью записывается в UTF-8 без BOM;
3. поток сбрасывается на диск;
4. если файл назначения существует, он заменяется из временного файла; иначе временный файл перемещается в конечное имя;
5. при ошибке временный файл удаляется по возможности.

Обычный сбой записи не должен оставлять обрезанную версию уже существовавшего файла. Это **не** автосохранение и **не** обещание спасения данных при полном отказе носителя или отключении питания. KeyER никогда не начинает автоматически сохранять текст при наборе или закрытии.

### 3. Диагностика Public Beta

В настройках есть шестой раздел «Диагностика». В нём можно:

- обновить локальный технический отчёт;
- просмотреть содержимое до передачи кому-либо;
- копировать отчёт в буфер обмена;
- явно сохранить его в указанный TXT-файл.

KeyER не отправляет отчёты на сервер, не регистрирует аккаунт и не использует внешний API.

Отчёт включает версию сборки и .NET, платформу ОС и архитектуру, схему настроек, количество профилей, режим Text/Code, тему, суммарное число профилей с включённой проверкой IDE и ограниченный список диагностических событий.

**Чего в нём нет:** содержимого текстового/кодового редактора, имён и путей файлов, названий сторонних окон, текста исключений, стека вызовов, имени пользователя, имени компьютера, комбинаций хоткеев, паролей и содержимого клавиатурного ввода.

Записи журнала допускаются только при строгом совпадении со структурой уже безопасного DiagnosticLog: метка времени, имя компонента, имя типа исключения и HRESULT. Неподходящие строки отбрасываются. Длина строки ограничена, включаются не более 25 последних подходящих событий. При недоступном или слишком большом журнале отчёт остаётся доступным без него.

### 4. Пакеты и контроль целостности

Windows Actions публикует установщик Windows, ZIP с переносной сборкой, расширение VS Code VSIX и отдельный TXT-манифест SHA-256. В манифесте присутствуют три контрольные суммы и соответствующие им имена файлов.

Сверить локальную сумму на Windows можно командой PowerShell:

    Get-FileHash .\KeyER-v0.9.0-Setup.exe -Algorithm SHA256

Эта проверка позволяет обнаружить повреждённую загрузку. Сама по себе контрольная сумма не заменяет проверку происхождения репозитория и безопасность исполняемого файла. Код не подписан коммерческим сертификатом.

## Контрольный перечень для тестирования на реальном Windows-ПК

- Запустить KeyER дважды: второе окно не должно появиться; после полного завершения первый слот можно использовать снова.
- Запустить из Portable и установщика отдельно: пользовательские настройки и профили остаются корректными.
- Создать и отредактировать исходник; сохранить новый файл с кириллицей, emoji и переводами строк.
- Перезаписать сохранённый файл другим содержимым; сравнить с ожидаемыми байтами.
- Отменить Save As: исходный текст и существующий файл не изменяются.
- Попробовать сохранить в папку без прав: KeyER сообщает об ошибке, существующий документ не должен становиться пустым.
- Проверить тему Dark/Light/System, навигацию и поле диагностики при DPI 100%, 125%, 150%.
- Открыть диагностику, проверить отсутствие пользовательских путей, исходного текста и имён окон.
- Экспортировать и вручную открыть отчёт; проверить, что он не был отправлен автоматически.
- Проверить глобальные горячие клавиши после закрытия и повторного открытия KeyER.
- Повторить нормальный набор, паузу, Stop и потерю фокуса в Блокноте, VS Code и Visual Studio.
- Сверить SHA-256 установщика, Portable ZIP и VSIX с опубликованным манифестом.

## Автоматические проверки

Windows CI выполняет существующие тесты Text/Code/Human/IDE и дополнительные регрессии: одиночный экземпляр, повторное получение mutex, запись и перезапись файла UTF-8, удаление временных файлов, отказ от записи на недопустимый путь, фильтрацию диагностического журнала и построение UI-раздела поддержки. Опционально создаются реальные WinForms-снимки главного окна и раздела диагностики.

## Ограничения и критерии 1.0.0

До стабильного 1.0.0 должны быть проверены разные мониторы и DPI, доступность интерфейса с клавиатуры, сценарии сохранения при отказах файловой системы, реальная совместимость SendInput в нескольких приложениях и сетевых IDE, а также устойчивость при долгих сеансах.

Полная совместимость со всеми программами **не заявляется**. KeyER не читает фактический текст в чужом редакторе без явно включённой поддержки IDE. Не стоит считать число отправленных клавиш доказательством точного результата.
