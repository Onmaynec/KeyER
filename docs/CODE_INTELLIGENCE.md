# Code Intelligence — KeyER v0.3.0

## Архитектура

Режим **Code** теперь работает через два отдельных компонента:

- `CodeAnalyzer` — лексический, **без потери данных** планировщик. Разбивает текст на строки и токены, хранит их точные смещения и различает идентификаторы, ключевые слова, строки, числа, комментарии, пробелы и операторы. Подсчитывает уровень блоков, исключая скобки в строках и комментариях.
- `CodeTypingEngine` — выполняет план через события клавиатуры, сохраняя символы исходника. Регулирует скорость и паузы с учётом контекста, имитирует исправляемые ошибки **только в идентификаторах и ключевых словах**, а по желанию повторно выделяет и перенабирает окончание идентификатора.

Это не полноценный компилятор или AST. Никакие файлы не запускаются, код не меняется автоматически и не отправляется в облако.

## Поддержка языков

При импорте файла язык определяется по расширению; для фрагментов без файла работают простые эвристики. В основном окне Code можно **выбрать язык вручную** — этот выбор приоритетнее расширения.

Языки: C#, C++, C, Python, JavaScript, TypeScript, Java, Go, Rust, HTML, CSS, JSON, XML, SQL, PowerShell, Shell, Ruby, PHP, Kotlin, Swift.

Токенизация учитывает стандартные блочные комментарии `/* ... */`, однострочные `//`, Python/Shell `#`, SQL `--`, HTML `<!-- ... -->` и Python тройные кавычки. Варианты экранирования и языковые расширения могут распознаваться приближённо. Исходник сохраняется независимо от правильности классификации токенов.

## Контекст набора

Алгоритм различает логические виды строк: импорт, определение типа, определение функции, ветвление, возврат, объявление переменной, комментарий, границу блока, разметку и обычную строку.

| Параметр профиля | Эффект |
| --- | --- |
| Пауза перед классом / функцией | Дополнительное время перед определениями |
| Пауза перед блоком / ветвлением | Дополнительное время перед структурными операторами |
| Пауза между строками | Задержка после каждого Enter |
| Пауза на синтаксисе | Задержка при `;`, `{`, `}`, `:` |
| Скорость идентификаторов | Множитель скорости при вводе имён |
| Скорость строковых литералов | Отдельный множитель для строк |
| Скорость комментариев | Отдельный множитель для комментариев |
| Проверка идентификаторов | Шанс выделить Shift+Left несколько последних букв и перенабрать их |

Паузы основаны на лексическом контексте. Они не означают, что KeyER выполняет анализ типов, поиск ошибок компиляции или планирование настоящего рефакторинга. Внутри заданного токена скорость меняется плавно. Уровень вложенности немного увеличивает паузу перед строкой.

## Точность и IDE

- Новый Code по умолчанию вводит **точно те же символы**, что были в исходном фрагменте, с нормализацией CRLF/CR в LF.
- В стандартном текстовом поле с предсказуемым вводом автотесты сравнивают результат после набора с исходным.
- Автоотступы и автоскобки в реальной IDE **нельзя надёжно определить только через SendInput**. Поэтому KeyER v0.3.0 не утверждает, что уже «понимает» состояние редактора.
- Старый экспериментальный переключатель очистки автоотступов может зависеть от поведения Home/End конкретной IDE; **по умолчанию отключён**.
- Отдельные адаптеры Visual Studio / VS Code, чтение настроек редактора, учёт IntelliSense и обратная сверка документа входят в v0.4.0.
- Не используйте эмуляцию ввода в неразрешённых окнах и защищённых полях.

## Разработка и тестирование

```powershell
dotnet run --project tests/KeyER.RegressionTests/KeyER.RegressionTests.csproj -c Release
```

Windows CI проводит: сохранение исходного текста после планирования для разных языков, проверку многострочных строк и комментариев, реальный выход виртуального редактора после случайных ошибок, работу Shift+Left, ручной выбор языка и контекстные задержки.

**Тесты используют виртуальный редактор, а не реальный Visual Studio.** До проверки на рабочем столе в настоящих IDE нельзя обещать посимвольную точность во всех конфигурациях.
