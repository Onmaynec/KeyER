# KeyER v0.5.0 — Human Behavior 2.0

## Стили поведения

В каждом профиле можно выбрать один из пяти стилей в разделе **Human Behavior 2.0**. Выбор стиля применяет набор параметров, но не блокирует последующую ручную настройку.

| Стиль | Символов/мин | Ошибки | Характер |
| --- | ---: | ---: | --- |
| Beginner | 130 | 6% | Медленный, короткие циклы концентрации, заметные паузы и исправления |
| Casual | 255 | 2,8% | Обычный ритм, умеренная усталость и паузы |
| Developer | 335 | 1,5% | Длинные интервалы концентрации, больше локальных просмотров кода |
| Professional | 465 | 0,6% | Быстрый, редкие ошибки, длительная концентрация |
| Custom | Не изменяет | Не изменяет | Сохраняет все текущие параметры пользователя |

Числа относятся к стартовым шаблонам. Скорость и частота ошибок остаются настраиваемыми в обычном редакторе профиля. Это не классификация реального пользователя и не результат машинного обучения.

## Концентрация и усталость

Модель `HumanBehaviorModel` хранит **состояние в пределах одной сессии**: длительность периода внимания (в символах), плавно меняющийся коэффициент концентрации и накопленную усталость. При достижении конца периода внимания может происходить небольшой перерыв, после которого усталость частично снижается.

- Новая цель концентрации выбирается случайно в заданном диапазоне, но фактическая скорость идёт к ней постепенно.
- Усталость накапливается по мере набора, увеличивая задержки. Длинный перерыв частично восстанавливает темп, а не сбрасывает всю историю сессии.
- Для Text после конца предложения или структурной паузы возможна дополнительная пауза на обдумывание.
- Для Code пауза на обдумывание может появляться перед классом, функцией или управляющей конструкцией. Профиль Developer использует их чаще.
- Все перерывы проходят через тот же отменяемый механизм ожидания, что и обычный ввод.

Эта модель полностью локальная. Платные API и нейросети не используются.

## Контролируемые действия курсора

**Просмотр недавно набранного слова** не изменяет текст: движок проходит на 1–N символов влево, делает небольшую паузу и возвращается на такое же количество вправо. Действие возможно только внутри одного непрерывного слова, состоящего из простых латинских/кириллических букв, цифр и подчёркиваний, **без выхода за границы слова**.

Контроль точности:
- Не используется Home, End, Ctrl+Left или Ctrl+Right: границы слов в IDE и браузерах могут различаться.
- Операции с курсором не пересекают emoji, комбинируемые Unicode-символы, табуляцию или переносы строк.
- При активной отложенной опечатке просмотр временно запрещён, пока ошибка не исправлена.
- В Code просмотр делается в конце идентификатора; редактирование последних букв через Shift+Left остаётся отдельной настройкой CodeReviewPercent.
- При смене активного окна или команде Stop в ходе просмотра дальнейший ввод прекращается.

## Совместимость и миграция

Существующие профили v0.4.0 сохраняются. При первом открытии настроек после обновления добавляются четыре готовых профиля Beginner, Casual, Developer и Professional, если профилей с такими названиями ещё нет. Уже созданные параметры пользователя остаются нетронутыми. Схема настроек обновляется до версии 3.

Продолжают работать Text 2.0, Code Intelligence 0.3, проверка VS Code и экспериментальная Visual Studio DTE-интеграция v0.4.0. Внешние редакторы могут по-разному обрабатывать курсор и автозамены. Точность подтверждена автоматическими тестами виртуального редактора; тесты в настоящих приложениях на Windows должны проводиться отдельно.

## Тестирование

В CI проверяются:
- Миграция старых настроек и идемпотентность регистрации шаблонов.
- Реальные параметры четырёх стилей и неприкосновенность настроек Custom.
- Воспроизводимость фокуса, длины перерывов и локальных просмотров при одинаковом seed.
- Точное сохранение текста и кода во всех стилях на 400 комбинированных прогонах с повышенной долей ошибок и симуляцией движения курсора.
- Все предыдущие регрессионные тесты Code, Text, IDE Bridge, VS Code extension и упаковки бинарников.

**Важно:** быстрый симулированный ввод не гарантирует, что чужой редактор не будет сам менять код. Для IDE рекомендуется опциональная сверка v0.4.0.
