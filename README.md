# KeyER

**KeyER** — настольное приложение для Windows 10/11: набирает подготовленный текст в активном окне через события клавиатуры, имитируя скорость, паузы, опечатки и их исправление.

**Новое в v1.1.0 — Humanizer 3.0:** единая модель человеческого ритма для Text и Code: расстояние между клавишами, чередование рук, повторный удар одним пальцем, коррелированные интервалы, микропаузирование перед сложными символами и более правдоподобные опечатки. Новый пресет «Естественный ритм», четыре настройки Humanizer и бережная миграция профилей без их сброса.

## Возможности v1.1.0 — Humanizer 3.0

- **Text 2.0**: естественный набор с плавной скоростью, быстрыми знакомыми сочетаниями букв, отдельным темпом для коротких и длинных слов, паузами после предложений, абзацев и между блоками текста.
- Ошибки в Text: пропуск, замена соседней клавишей, повтор и перестановка букв; немедленные исправления и возврат спустя несколько слов через Backspace, Delete, Shift+Left и стрелки.
- Настраиваемая обработка Enter (Enter либо Shift+Enter) и Tab (физическая клавиша либо 1–8 пробелов). Профиль «Переписка» использует Shift+Enter.
- Готовые профили «Обычный текст» и «Переписка», а также поддержка миграции 0.1.x с сохранением собственных профилей.
- **Humanizer 3.0:** общий моторный ритм для Text/Code с физическим расстоянием между клавишами, чередованием рук, повторными ударами пальца и плавными скоростными сериями.
- **Контекстное мышление:** правдоподобные микрозадержки перед заглавными буквами, цифрами, скобками, операторами и сменой раскладки; без одинаковых пауз на каждом символе.
- **Опечатки 3.0:** соседние клавиши русской/английской раскладок (включая диагонали), зависимость ошибок от сложности перехода и распределение замен, пропусков, повторов, перестановок.
- **Настройки Humanizer:** интенсивность, расстояние, память ритма и микрозадержки; новая конфигурация «Естественный ритм». Старые профили сохраняются при схеме настроек v4.
- **Стабильность v1.0:** при повреждении settings.json сохраняется исправный backup; испорченный файл отдельно архивируется и не подменяет ранее исправные данные.
- **Горячие клавиши v1.0:** новый набор регистрируется согласованно, с попыткой отката к прежнему при конфликте; обычная смена темы не прерывает регистрацию.
- **Остановка v1.0:** отменённый обратный отсчёт и поздний ответ IDE не должны начинать ввод после Stop.
- **Проверки v1.0:** 270 дополнительных детерминированных сессий, тесты миграции профилей и испорченных настроек, обязательная проверка реальных UI-снимков из Windows CI.
- **Public Beta v0.9:** один активный экземпляр KeyER на пользовательский сеанс Windows; повторный запуск показывает сообщение вместо конфликта глобальных горячих клавиш.
- **Сохранение документа:** файл записывается во временную копию рядом с оригиналом, затем заменяется. При ошибке исходный файл не должен оказаться наполовину перезаписанным. Сохранение выполняется только по действию пользователя.
- **Бета-диагностика:** «Настройки» → «Диагностика» — предпросмотр, обновление, копирование и сохранение отчёта. Отчёт содержит версии компонентов, тип ОС, число профилей и только подходящие под строгий формат записи ошибок. **Ни исходный текст, ни путь к файлу, ни имя пользователя не экспортируются**.
- **Проверяемые загрузки:** GitHub Actions вместе с Setup, Portable и VSIX создаёт файл SHA256SUMS.txt для проверки целостности. Нет фоновой отправки отчётов и автоматических обновлений.
- **Совместимость v0.8:** предварительная проверка выбранного окна перед стартом; учитываются фокус, существование, сворачивание, зависание и повышенные права приложения. Проверка сообщает понятную причину отказа и инструкцию, как исправить ситуацию.
- **Проверка без набора:** кнопка «Проверить окно» в панели управления запускает трёхсекундный отсчёт. После переключения в нужное окно KeyER показывает отчёт. Проверка не вводит символы и не читает содержимое окна.
- **Дополнительная защита:** во время отправки клавиш отслеживается не только HWND, но и PID целевого процесса. Если пользователь неожиданно зажимает Ctrl, Alt, Shift или Win, набор останавливается, не выполняя потенциально опасное сочетание.
- **Отчёт последнего запуска:** результат (завершено, остановлено, потерян фокус, клавиатурное вмешательство, ошибка), обработанные символы, длительность и рекомендация. Сводка существует только в памяти до закрытия программы; без текста кода, заголовков окон и истории файлов.
- **UX v0.7:** полноценное пустое состояние редактора с кнопками вставки и открытия файла, подсказки запуска в боковой панели, краткая информация о скорости и опечатках выбранного профиля, приблизительное время набора без учёта пауз.
- **Файлы:** сохранение текста вручную через «Сохранить» или Ctrl+Shift+S, открытие с перетаскиванием в редактор, предупреждение о потере несохранённых изменений при замене и подтверждение очистки. Текст **не сохраняется автоматически** без разрешения пользователя.
- **Поиск:** количество совпадений, переходы вперёд/назад, циклическое перемещение, поиск с учётом регистра, поиск выделенного фрагмента и клавиатурное управление. Лимит до 10 000 совпадений предотвращает зависание на больших исходниках.
- **Настройки:** поиск параметров внутри выбранной категории, более читаемые поля, вкладка оформления с **живым предпросмотром справа** до сохранения изменений.
- **Интерфейс Studio v0.6:** боковая панель Text / Code, выбор текущего профиля, быстрые переключатели темы, компактного режима и закрепления окна; собственная иконка приложения.
- **Редактор:** RichTextBox с номерами строк и позициями Ln/Col, цветной лексической подсветкой кода, поиском (Ctrl+F), быстрыми действиями «Вставить», «Файл», «Копия», «Очистить» и счётчиком символов и слов.
- **Управление вводом:** крупные кнопки «Начать», «Пауза», «Стоп», собственная шкала прогресса и статус. На узком окне элементы адаптируются, менее важные команды скрываются.
- **Настройки:** отдельные разделы «Поведение», «Обычный текст», «Режим Code», «Горячие клавиши», «Оформление». Внешний вид не хранится внутри профиля набора.
- **Оформление:** Dark / Light / System; акценты Iris, Ocean, Mint, Amber; настройка размера шрифта, подсветки синтаксиса и номеров строк. Параметры сохраняются автоматически в settings.json.
- **IDE Integration v0.4**: проверка итогового кода в VS Code через локальное расширение и в Visual Studio через DTE. Проверяемые сессии требуют пустой документ и один курсор в начале. Возможны режимы «Только проверить» и «Проверить и исправить», а также обычный ввод без интеграции.
- Расширение VS Code сообщает настройки автозакрытия скобок, автокавычек, автоотступов и форматирования. При смене вкладки или окна отменяет сессию; исходный код не отправляется в интернет. Исправление по явному выбору выполняется через API редактора **только после** имитации клавиатурного набора.
- Visual Studio 2022: экспериментальная проверка пустого документа через DTE/COM с подбором экземпляра по PID и проверкой активного документа.
- **Code 0.3**: отдельный лексический анализатор с выбором языка, отслеживанием комментариев, строк и вложенности блоков. Планирование набора функций, классов, импортов, управляющих конструкций, переменных, комментариев и обычных строк.
- Для Code — настраиваемые паузы перед функциями/классами и блоками, темп печати идентификаторов, строк и комментариев; ошибки только внутри ключевых слов и имён, с обязательным исправлением. По желанию — безопасное локальное выделение окончания идентификатора через Shift+Left и повторный набор.
- Поддерживается определение 20 языков по расширению; для фрагментов без файла — эвристики; язык можно выбрать вручную в главном окне.
- Набор Unicode-символов (английский, русский и другие языки), переводов строк и табуляций.
- Случайная скорость, серии быстрого набора, редкие паузы, усталость и четыре типа исправляемых ошибок: подмена, пропуск, повтор, перестановка символов.
- Исправление после нескольких последующих символов при помощи стрелок, Backspace и повторного набора.
- Настраиваемые **глобальные** горячие клавиши старта, паузы и остановки.
- Предустановленные и пользовательские профили; настройки сохраняются в `%LOCALAPPDATA%\KeyER\settings.json`.
- Проверка целевого окна перед каждым вводимым действием и остановка при смене фокуса.
- Набор начинается после отпускания модификаторов глобального хоткея; Ctrl+Alt+F5/F6/F7 не требуют клавиши Win.
- Безопасный симметричный жест проверки курсора вместо Home/End.
- Атомарная запись настроек с резервной копией и восстановлением.
- Диагностика в %LOCALAPPDATA%\KeyER\diagnostics.log без записей набираемого текста, названия окна и имён файлов.
- Переносной EXE и установщик Windows из GitHub Actions (Inno Setup).

## Запуск из исходников

Установите [**.NET 8 SDK**](https://dotnet.microsoft.com/download/dotnet/8.0) на Windows 10/11.

```powershell
dotnet run --project src/KeyER/KeyER.csproj -c Release
```

Или опубликуйте portable-сборку:

```powershell
dotnet publish src/KeyER/KeyER.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o dist/KeyER
```

Для Portable ZIP, установщика и VS Code VSIX см. вкладку **Actions** → **Windows build** → **Artifacts**; в репозитории нет заранее собранных бинарников.

## Проверяемый Code в VS Code / Visual Studio

1. **VS Code:** установите артефакт `KeyER-VSCode-1.1.0.vsix` через меню Extensions → ... → Install from VSIX. Расширение локальное и работает только в настольном редакторе Windows.
2. **Visual Studio 2022:** дополнительное расширение не требуется — KeyER пробует подключиться к автоматизации DTE/COM активной IDE. Это экспериментальный адаптер; он может не работать в некоторых конфигурациях.
3. Откройте **новый пустой текстовый документ** в IDE и поставьте единственный курсор в начало.
4. В KeyER выберите **Code → Настройки профиля → IDE: проверка итогового кода**. Для автоматического исправления установите «Проверить и исправить».
5. Перейдите в окно IDE и нажмите Ctrl+Alt+F5. В конце KeyER сравнит результат с исходным кодом и сообщит, совпал ли он. Исправление выполняется только в режиме «Проверить и исправить» и **не сохраняет файл на диск**.

При отключённой проверке продолжается прежний режим реальных событий клавиатуры. Если включена проверка, но редактор не подключён или файл не пустой, KeyER **не начинает** набор, чтобы не обещать неподтверждённую точность.

Подробнее: [интеграция IDE](docs/IDE_INTEGRATION.md) и [расширение VS Code](extensions/vscode/README.md).

## KeyER v1.1.0 — как настроить максимально естественный ввод

В **Настройки → Поведение** выберите профиль **«Естественный ритм»** либо задайте вручную моторную интенсивность (80–100%), влияние расстояния (70–100%), память ритма (70–90%) и микрозадержки (8–18%). Это пример сочетания параметров, а не «подтверждённый» биометрический профиль конкретного человека.

В Text сохраняются паузы после предложений, абзацев, исправления и внимание. В Code дополнительно учитываются синтаксические контексты и скорость разных типов токенов. В обоих режимах действует одна модель моторики.

Модель работает **локально**, не собирает чью-либо историю ввода и не гарантирует неотличимости от реального человека. Подробности: [Humanizer 3.0](docs/HUMANIZER_3.md).

## Бета-версия: диагностика и сохранность данных

Для отчёта об ошибке откройте **Настройки → Диагностика → Обновить**. Перед экспортом можно проверить отображаемый текст. **«Сохранить отчёт»** записывает обычный TXT-файл только в выбранную вами папку; приложение не отправляет его автоматически. В отчёте нет исходника, названий файлов или заголовков целевых окон.

Для сохранения исходника используйте **Ctrl+S / Ctrl+Shift+S** либо кнопку «Сохранить». В v0.9 данные сначала записываются во временный файл в той же папке, затем происходит замена — без автосохранения содержимого редактора.

При запуске второго экземпляра появится предупреждение; следует вернуться к уже открытому KeyER. Это не система синхронизации нескольких копий и не сетевой сервис.

Для проверки загруженных файлов сравните SHA-256 установщика, Portable и VSIX с **SHA256SUMS.txt** из артефактов финального CI-прогона. В Windows используйте PowerShell Get-FileHash с параметром -Algorithm SHA256.

Подробнее: [Public Beta v0.9](docs/PUBLIC_BETA_0.9.md).

## Как проверить совместимость перед вводом

1. В KeyER подготовьте текст и выберите профиль. При желании нажмите **«Проверить окно»**.
2. За три секунды переключитесь в целевое приложение и установите курсор в нужное поле.
3. В отчёте будет указано, отвечает ли окно, не изменилось ли оно и не мешают ли повышенные права. Это не проверка содержимого поля и не гарантия, что приложение примет все клавиши.
4. Запустите набор обычным способом: **Ctrl+Alt+F5** или кнопкой Start с обратным отсчётом.
5. По окончании либо прерывании нажмите **«Отчёт»** рядом с процентом выполнения. Изучите рекомендации, прежде чем повторять ввод.

При остановке KeyER **не продолжает автоматический набор с последнего символа**: редактор мог самостоятельно изменить текст, а ошибки и перемещения курсора могли быть незавершены. Сначала проверьте целевой документ вручную.

Подробно: [Reliability & Compatibility 0.8](docs/RELIABILITY_0.8.md).

## KeyER Studio v0.7: быстрый сценарий

1. Слева выберите режим Text или Code и подходящий профиль. На боковой панели указаны скорость и вероятность опечаток.
2. В центре редактора нажмите «Вставить текст» или «Открыть файл», либо перетащите текстовый файл в окно. Пустой редактор показывает подсказку.
3. По желанию сохраните текущий исходник через **Ctrl+S** (или Ctrl+Shift+S). Замена изменённого текста другим файлом и очистка требуют подтверждения.
4. Перейдите в другое приложение и установите там курсор. Используйте горячую клавишу запуска либо кнопку с обратным отсчётом.
5. Следите за процентом прогресса и статусом внизу. Полный текст длинного статуса доступен при наведении.

Дополнительные возможности: **Ctrl+F** — поиск с количеством совпадений и переключателем регистра; **Enter/Shift+Enter** — следующее/предыдущее совпадение; **Esc** — закрыть поиск. В настройках можно найти нужный параметр через поле поиска, не пролистывая длинный список.

Подробнее о безопасном редактировании, поиске и живом предпросмотре: [docs/UX_0.7.md](docs/UX_0.7.md).

## Управление рабочим пространством

- Слева выберите **Text** или **Code** и профиль набора. В Code над редактором появляется выбор языка.
- Команды над редактором: вставка текста, импорт файла, ручное сохранение, копирование и очистка. **Ctrl+F** открывает поиск по исходнику, Enter — следующее совпадение, Shift+Enter — предыдущее, Esc — закрыть.
- Внизу расположены запуск, пауза и остановка, а также прогресс и настроенные горячие клавиши.
- В левой панели можно быстро переключить тему, компактность интерфейса и режим поверх других окон.
- В «Настройках» → «Оформление» можно выбрать тему Windows, цветовой акцент, размер шрифта, номера строк и подсветку кода.
- Размеры окна сохраняются при изменении размера вручную. Даже в компактном режиме окно остаётся масштабируемым.

Описание устройства UI, ограничений и управления цветом: [docs/UI_DESIGN.md](docs/UI_DESIGN.md).

## Быстрый старт

1. Вставьте текст или код в окно KeyER; выберите **Text** или **Code** и профиль.
2. Откройте целевое приложение и поставьте курсор в нужное место.
3. Нажмите **Ctrl+Alt+F5** для старта (либо кнопку «Начать» в KeyER и переключитесь в целевое окно за время отсчёта).
4. **Ctrl+Alt+F6** — пауза/продолжить; **Ctrl+Alt+F7** — остановить. Все сочетания настраиваются.
5. Во время набора не печатайте вручную в целевом окне, иначе результат может отличаться.

## Важные ограничения

KeyER не использует буфер обмена для вывода. Для ввода применяется Win32 `SendInput` с Unicode-событиями. Это не гарантирует совместимость с *каждым* приложением: некоторые поля, игры, терминалы и привилегированные окна блокируют синтетический ввод. Запуск KeyER без прав администратора не позволяет вводить данные в приложение, запущенное с повышенными правами (UIPI).

**Важно для Text:** в обычных текстовых полях Tab может переключать фокус, а Enter в мессенджере может отправить сообщение. Для Telegram и подобных чатов выбирайте профиль «Переписка» (Shift+Enter) и заранее проверяйте поведение поля ввода. Вывод не считывается обратно из чужой программы, поэтому KeyER не подтверждает побайтовое совпадение введённого текста в каждом приложении. При выборе «Пробелы вместо Tab» итог намеренно отличается от оригинального символа табуляции.

**Code** анализирует текст лексически и может проверить результат в поддерживаемых IDE, если включена опциональная интеграция. Обычная эмуляция не имеет доступа к содержимому чужого редактора. Даже с интеграцией автозамены и плагины могут менять текст после проверки; режим «Проверить и исправить» исправляет содержимое пустого документа через IDE API в конце набора, но не гарантирует точность промежуточных экранных действий. В других программах, в непустых документах и при выключенной интеграции точное совпадение не подтверждается. «Очистка автоотступа» экспериментальная.

Управляющие последовательности и хоткеи не предназначены для обхода ограничений приложений. Используйте программу только в собственных окнах/с разрешения владельца.
